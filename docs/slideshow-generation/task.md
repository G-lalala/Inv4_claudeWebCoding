# スライドショー生成機能 タスク一覧

## タスク

### 環境構築

#### 1. FFmpeg セットアップ
- [ ] Dockerfile に FFmpeg インストールコマンド追加
- [ ] FFmpeg のバージョン確認とテスト
- [ ] 必要なコーデック（libx264, AAC）の確認

### AI 画像分析

#### 2. AI 分析機能
- [ ] `aiAnalyzer.ts` ファイル作成
- [ ] 使用する AI モデルの選定（GPT-4 Vision / Claude / OSS）
- [ ] 画像を AI API に送信する処理
- [ ] 分析結果から表示時間（3〜5秒）を判定
- [ ] API失敗時のフォールバック処理（デフォルト4秒）
- [ ] レート制限対応

### Ken Burns 効果

#### 3. Ken Burns エフェクト実装
- [ ] `kenBurns.ts` ファイル作成
- [ ] 6種類の動きパターンを定義:
  - [ ] ズームイン
  - [ ] ズームアウト
  - [ ] パン左
  - [ ] パン右
  - [ ] パン上
  - [ ] パン下
- [ ] FFmpeg zoompan フィルターのパラメータ生成
- [ ] ズーム倍率（1.0x 〜 1.2x）の調整
- [ ] ランダム選択または順番適用のロジック

### トランジション効果

#### 4. トランジション実装
- [ ] `transitions.ts` ファイル作成
- [ ] 5種類のトランジションパターンを定義:
  - [ ] フェード
  - [ ] クロスディゾルブ
  - [ ] スライド（横）
  - [ ] スライド（縦）
  - [ ] ズームフェード
- [ ] FFmpeg xfade フィルターのパラメータ生成
- [ ] 切り替え時間（0.5〜1秒）の設定
- [ ] ランダム選択ロジック

### FFmpeg 統合

#### 5. FFmpeg ラッパー
- [ ] `ffmpeg.ts` ファイル作成
- [ ] Node.js から FFmpeg を実行する処理
- [ ] 画像の scale と pad フィルター適用（16:9、黒帯追加）
- [ ] Ken Burns + トランジションの統合
- [ ] 複数画像の連結処理
- [ ] エラーハンドリング（リトライ最大3回）
- [ ] 進捗情報の取得（FFmpeg stderr パース）

#### 6. 動画生成パイプライン
- [ ] 画像一覧の取得（メタデータ読み込み）
- [ ] 各画像の表示時間を AI で分析
- [ ] Ken Burns効果の割り当て
- [ ] トランジション効果の割り当て
- [ ] FFmpeg コマンドの組み立て
- [ ] FFmpeg 実行とエラーチェック
- [ ] 生成された動画ファイルの検証

### API エンドポイント

#### 7. 動画生成API
- [ ] `app/api/generate/route.ts` 作成
- [ ] リクエストパラメータ検証（session-id）
- [ ] 画像ファイルの存在確認
- [ ] AI分析 → Ken Burns → トランジション → FFmpeg の実行
- [ ] 進捗情報の返却（WebSocket or ポーリング用エンドポイント）
- [ ] 生成完了後のレスポンス（動画ファイルパス）

### テスト

#### 8. ユニットテスト
- [ ] Ken Burns ロジックのテスト
- [ ] トランジション選択ロジックのテスト
- [ ] FFmpeg コマンド生成のテスト

#### 9. 統合テスト
- [ ] 3枚の画像で動画生成テスト
- [ ] 50枚の画像で動画生成テスト
- [ ] 異なるアスペクト比の画像混在テスト
- [ ] AI分析失敗時のフォールバックテスト
- [ ] FFmpeg失敗時のリトライテスト

### パフォーマンス最適化

#### 10. 最適化
- [ ] 並列処理可能な部分の特定
- [ ] メモリ使用量の監視
- [ ] 処理時間の計測とボトルネック分析
- [ ] プログレス通知の実装（WebSocket or ポーリング）

## 依存関係
- **依存**: image-upload（画像ファイルとメタデータが必要）
- **依存**: bgm-management（BGM統合のため）
- **提供**: video-output（生成された動画ファイル）

## 備考
- FFmpeg のフィルター処理は複雑なため、段階的に実装
- AI API のコスト・レート制限に注意
- 処理時間が長いため、ユーザーへの進捗通知が重要
